initialize 的 make_current=True 分支条件取反，导致总是抛异常或从不抛异常

tornado/ioloop.py:251
问题说明
initialize 中 make_current 为真时，本意是“若已存在 current IOLoop 则报错，否则把自己设为 current”。但代码写的是 `if IOLoop.current(instance=False) is None: raise RuntimeError(...)`，条件与语义相反：当当前线程没有 current IOLoop（正常可设置的情况）时反而抛 RuntimeError；当已经存在 current IOLoop 时却静默覆盖它。这与 make_current=None 分支（current 为 None 时才 make_current）的逻辑也不一致。
触发条件
IOLoop(make_current=True) 在尚无 current IOLoop 的线程中构造：current(instance=False) 返回 None，进入 raise 分支，抛出 RuntimeError("current IOLoop already exists")，尽管实际上并不存在冲突。
代码依据
248-250 行：`if make_current is None: if IOLoop.current(instance=False) is None: self.make_current()`；251-254 行：`elif make_current: if IOLoop.current(instance=False) is None: raise RuntimeError("current IOLoop already exists"); self.make_current()`。两分支对同一条件 `is None` 的处理相反，且异常消息与触发条件矛盾。
修复建议
将条件改为 `if IOLoop.current(instance=False) is not None: raise RuntimeError("current IOLoop already exists")`，再调用 self.make_current()。
复核理由
测试在 clear_current 后确认 current(instance=False) 为 None，再构造 IOLoop(make_current=True)，实际调用到 ioloop.py:253 并抛出 RuntimeError('current IOLoop already exists')，与候选描述一致。make_current 文档明确说明显式调用 make_current 可使该 IOLoop 成为当前线程的 current，且 4.1 起无 current 时创建会自动成为 current；因此无 current 时 make_current=True 应成功设置而非报错。条件 `is None` 与异常语义相反，属行为缺陷。
验证方式
两次独立隔离执行出现同类型失败并触达目标代码；预期依据通过结构化准入检查与模型对照引用原文核验，仍供维护者复查。

import unittest
from tornado.ioloop import IOLoop


class ReproductionTest(unittest.TestCase):
    def test_reproduction(self):
        IOLoop.clear_current()
        self.assertIsNone(IOLoop.current(instance=False))
        loop = IOLoop(make_current=True)
        try:
            self.assertIs(IOLoop.current(instance=False), loop)
        finally:
            IOLoop.clear_current()
            loop.close(all_fds=True)
