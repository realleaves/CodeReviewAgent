# 真实 DeepSeek 发现对照与新样本验证（2026-10-15～10-21）

**实验已结束，未证实真实缺陷发现能力提升。** 保留默认 `legacy` 上下文、thinking disabled、最大输出6000。共计扣减 **436/600** 个请求名额，包含失败、格式纠正和一次送达情况不明的中断，剩余164次不再使用。没有推送 GitHub。

完成 legacy/callgraph 对照、最多两轮单变量改进，再对一个独立复现的额外发现信号做预选新样本验证。共260个计划窗口，成功与失败全部保留。主评分仍为冻结的参考问题识别，Codex辅助判读待人工复查；这是已知位置窗口测试，不是全仓库准确率，也不替换历史 **1/26** 的有效自动生成证据成绩。

## 开发对照

固定6个历史漏检样本：tornado-1/3/7、youtube-dl-2/4/8，两个版本、两次重复。每轮72个窗口，采用相同生产源码、候选规则、提示词、只读工具、每窗口最多3次请求和45秒SDK超时，只切换列出的变量。代码按SHA256保存独立副本；失败和重试全部计数，SDK自动重试关闭。

| 对照 | 完整窗口 | 请求名额 | 参考问题正确区分：重复1；重复2 |
|---|---|---:|---|
| r0 legacy | 33/36 | 60 | 0/3；0/6 |
| r0 callgraph | 33/36 | 39 | 0/5；0/6 |
| r1 思考关闭，callgraph | 31/36 | 38 | 0/4；0/5 |
| r1 思考开启，callgraph | 17/36 | 81 | 无完整对；0/1 |
| r2 思考开启，输出6000 | 14/36 | 72 | 0/1；无完整对 |
| r2 思考开启，输出12000 | 13/36 | 74 | 无完整对；无完整对 |

表中分母是各组可评分的完整缺陷/修复对，不能忽略失败后跨分母比较。“无完整对”的率值为null，不写成0%。r0第一次共同完整3对、第二次6对，两组均未识别参考问题。r1共同完整对分别0与1；r2两次均无共同完整对，无法据此估计真实效果差异。

- **r0：上下文假设。** 调用关系补充未带来参考命中。callgraph本轮请求比legacy少35%（39对60），这是限定样本的消耗差异，不能解释为发现能力提高；后续仅用它作为较低成本的固定上下文。
- **r1：推理假设。** 同一输入切换thinking。开启组有16次长度失败、2次JSON解析失败和1次连接错误；完整度明显下降，没有达到采用条件。
- **r2：输出瓶颈假设。** thinking保持开启，只将输出6000改为12000。6000组有12次长度失败、8次连接错误；12000组没有长度失败，但有12次连接错误、6次API超时，以及格式/结构失败和一次进程中断。增加输出解决了已观测的截断，未恢复完整运行，不能把所有失败笼统归因于模型能力。

另有1次thinking启动前探测计入预算。因此开发部分总计365，而不是仅表中364次。

## 额外问题：独立复现，单独报告

开启思考组多次报告 `check_origin` 对Origin主机名小写化、Host值保留原样，导致同一主机仅大小写不同时握手误拒。关闭组没有提出这一具体问题，但其他额外候选未全部判真，不能推算全局精确率或整体新增缺陷数。

评测者编写真实本地握手测试，缺陷版和参考修复版都是“小写对照通过、大写Host返回403”；仅在独立副本将Host同样小写化后，两项均通过，共3个隔离容器、0次模型调用。主机名比较的依据见 [RFC3986 §3.2.2](https://www.rfc-editor.org/rfc/rfc3986#section-3.2.2)。证据支持这是一个实际行为问题，仍待维护者复查。

参考修复改的是set_nodelay，此问题两侧仍存在；它不计tornado-1参考命中，也不计Agent自行生成的证据。评测者测试、全部日志和副本更改均单独保留，未改写原候选、原快照或答案。另有两个r0额外候选的独立反证，也完整保留。

## 预选新样本验证

原10月18日检查点写“没有参考增益，因此未启动新验证”。复核上述额外问题的运行对照后，增加了**探索性验证**，主要采用门槛不变。新样本ID早在开发调用前选定：tornado-13、youtube-dl-14、tornado-14、youtube-dl-15。先冻结候选配置，再查看新参考语义并在模型调用前冻结新问题描述；沿用原评分函数和具体根因/有效触发规则。未更改原20问题参考答案。

两组均callgraph、最大输出6000，只比较thinking开关；两个版本、两次重复，共44窗口。官方回归测试在4/4样本上均实现缺陷版失败、修复版通过（8个容器）。Agent只得到生产代码和同版本索引，不获得测试、补丁、标签或相反版本。

| 新样本条件 | 完整窗口 | 调用 | 重复1正确区分/有效对 | 重复2正确区分/有效对 |
|---|---|---:|---:|---:|
| 思考关闭 | 22/22 | 22 | 2/4 | 1/4 |
| 思考开启 | 11/22 | 49 | 1/1 | 1/1 |

**开启组的1/1不是更高能力的证明：每次有3/4计划缺陷对不完整，双方共同可评分的都只有tornado-14，两组均识别。** 关闭组两次均识别tornado-14，第一次另识别youtube-dl-15的科学计数法问题，第二次未重复识别，显示输出仍有波动。所有同参考问题修复版告警为0，不代表没有其他误报。

验证没有支持默认采用thinking；不追加调参、不把开发集成绩写成泛化收益。当前工作区另有取证预期准入改动，本验证不运行取证阶段；发现提示与候选schema的等价核对保存在归档中，未把该改动混入发现结果。

## 中断、记录与限制

- r2请求0365已扣预算但没有响应落盘；核对原进程已不存在，按失败保留，送达情况未知，不退款、不补写响应、不重试。
- 新验证保存42/44窗口后进程退出；确认没有未配对请求且源码哈希一致后，只续跑最后两个未启动窗口，保留断点原件和续跑驱动。没有重试任何已失败窗口。跨日期续跑以及服务端模型别名无法固定权重快照，是环境限制。
- 记录每次初始输入、工具对话、可用回答、错误、usage与冻结源码。早期r0的生成参数保存在manifest/调用记录，后续另存逐请求参数。SDK在长度错误时未返回到上层的部分消息无法恢复；中断0365也没有原始回答。这些缺失已明确保留，不能声称全部HTTP响应完整。
- tokens只累计服务端已返回的usage，不能据此精确还原无usage失败请求的费用。436是本地保守扣减次数，不是服务商账单。
- 6个开发样本是历史漏检样本，4个新样本也很小；不能据此报告总体精确率、全仓库召回率或统计显著提升。
- 本轮没有训练DeepSeek权重，未修改参考评分器，未把评测者修正计为Agent成果。
